# `diff_census.py` — design

A general-purpose git diff line counter with user-defined groupings and optional
budget enforcement. It is the PR size gate of the stacked-planning skills.

This is the design the script was built from. The script's reference,
[`DIFF_CENSUS.md`](../skills/authoring-stacked-plans/scripts/DIFF_CENSUS.md),
describes it as built and wins where the two differ.

Target: Python 3.11+ (uses stdlib `tomllib`).

---

## 1. Purpose

Count additions and deletions between two git refs, classify every changed line
into user-defined buckets, and optionally fail when a bucket exceeds its budget.

A size gate that hardcodes one policy — 400 production lines, 1200 all-in,
additions plus deletions, 10% grace band — fits one repository. Here that policy
is configuration rather than code, and the tool is reusable for any "how much of
what kind of change is in this diff" question.

Two modes:

- **Census** — count and report. No pass/fail judgement.
- **Gate** — census, plus enforce limits and signal via exit code.

---

## 2. Core concepts

There are three kinds of object in a config, and keeping them distinct is the
main structural idea in this design.

| Object | Purpose | Produces a bucket? | Has a limit? |
|---|---|---|---|
| **Global exclusion** | Lines that are not a review surface at all | Yes — `exempt` | No |
| **Matcher** | A named, reusable rule set | Only if `report = true` | No |
| **Group** | A budgeted category of change | Yes | **Required** |

A matcher is a *definition* ("what counts as generated code"). A group is a
*budget* ("production code must stay under 400 lines"). Groups reference
matchers via the `matches` facet, which is how `production` is defined as
"source directories, minus generated, minus tests, minus docs, minus comments"
without restating any of those definitions.

If you want a bucket in the output with no budget attached, that is a matcher
with `report = true`, not a group.

### 2.1 Buckets

Every changed line lands in exactly one of `exempt` or `total`.

- **`exempt`** — matched a global exclusion rule. Terminal: excluded lines are
  invisible to all matchers and groups. Broken down in the output by which
  global rule caught them.
- **`total`** — everything else. The denominator for all group accounting.
- **Groups and reported matchers** — subsets of `total`. A line may belong to
  zero, one, or many. Group memberships need not sum to `total`.
- **`unmatched`** — lines in `total` claimed by no group and no reported
  matcher. This is the config-coverage metric: a large `unmatched` means the
  config does not describe this repository.

Global exclusion being terminal is deliberate. It keeps classification a single
forward pass with no back-references, makes `total + exempt` a genuine partition
of the diff, and lets `--explain` print one linear trace per line. The
composition need that would otherwise argue for a "rescue" mechanism is served
by matchers instead.

## 3. Configuration

### 3.1 Format and location

TOML, namespaced under a `[diff_census]` table inside the shared Stacked
Planning `config.toml`, so sibling scripts (`stack_overlap.py`, others) can
share one file without key collisions.

Resolution order for the config path:

1. `--config PATH` (explicit; error exit 2 if unreadable)
2. `$STACKED_PLANNING_CONFIG`
3. `.agents/plugins/stacked-planning/config.toml`, relative to the git toplevel

If none is found, run with built-in defaults only: the built-in global exclusion
list, no matchers, no groups. Census mode works; gate mode fails (§7.3).

### 3.2 Example

```toml
[diff_census]
version = 1
overlap = "multi"                    # "multi" | "first_match_wins"
docstrings_as_comments = true

[diff_census.global]
extend_builtin = true                # false = replace built-in defaults entirely
exclude = [
  { path = ["**/*.lock", "**/package-lock.json", "**/go.sum"] },
  { path = ["**/vendor/**", "**/node_modules/**", "**/*.min.js"] },
  { content = '^\s*$' },
]

# ---- matchers: definitions, no budget -------------------------------------

[diff_census.matchers.generated]
report = true
rules = [
  { content = '@generated|Code generated by' },
  { path = ["**/*.pb.go", "**/*_pb2.py", "**/migrations/**"] },
]

[diff_census.matchers.tests]
report = true
rules = [
  { path = ["tests/**", "**/*_test.py", "**/*_test.go", "**/conftest.py"] },
]

[diff_census.matchers.docs]
report = true
rules = [
  { ext = ["md", "rst", "txt"] },
  { path = ["docs/**"] },
]

[diff_census.matchers.comments]
report = true
rules = [
  { comment = ["only"] },
]

# ---- groups: budgets ------------------------------------------------------

[diff_census.groups.production]
limit = { changed = 400, grace = 0.10 }
include = [
  { path = ["src/**", "lib/**"] },
]
exclude = [
  { matches = ["generated", "tests", "docs"] },
  { comment = ["only", "trailing"] },
]

# ---- census-wide limits (optional) ----------------------------------------

[diff_census.limits]
total = { changed = 1200, grace = 0.10 }
unmatched = { changed = 50 }
```

Inline tables keep rule lists readable at this nesting depth. The array-of-
tables form (`[[diff_census.groups.production.include]]`) is equivalent and may
be used for rules too long for one line, but the two styles cannot be mixed for
the same key.

### 3.3 Rule semantics

A **rule** is a table of facets. A **rule list** is an array of rules.

- **Within one rule, facets AND together.** `{ path = ["src/**"], ext = ["py"] }`
  requires both.
- **Within one facet, values OR together.** `path = ["src/**", "lib/**"]` is
  either.
- **Across rules in a list, OR.** Each entry is an alternative.

This is disjunctive normal form. There is deliberately no `not` operator —
negation is what `exclude` is for.

Group evaluation:

```
member(line, group) := matches_any(group.include) AND NOT matches_any(group.exclude)
```

`include` omitted defaults to "matches everything", which makes an
exclusion-only group the degenerate case of the same mechanism rather than a
special form.

Matcher evaluation is `matches_any(matcher.rules)`.

### 3.4 Facets

| Facet | Matcher type | Notes |
|---|---|---|
| `path` | glob (gitwildmatch) | repo-relative, no leading slash |
| `path_regex` | regex | full repo-relative path |
| `dir` | glob | dirname only |
| `name` | glob | basename only |
| `name_regex` | regex | basename only |
| `ext` | exact, case-folded | no leading dot; empty string `""` for no extension |
| `mime` | exact or `type/*` | e.g. `"text/x-python"`, `"image/*"` |
| `size` | comparison string | see below |
| `mode` | exact octal string | `"100644"`, `"100755"`, `"120000"`, `"160000"` |
| `content` | regex | line text, leading `+`/`-` stripped |
| `change` | `"add"` \| `"del"` | |
| `comment` | `"only"` \| `"trailing"` \| `"none"` \| `"unknown"` | §5 |
| `matches` | matcher name(s) | §3.5 |

All facets accept a scalar or an array; a scalar is treated as a
single-element array.

**`size` grammar:** `<op><space?><number><unit?>` where op is one of
`< <= > >= == !=`, and unit is one of `B KiB MiB GiB` (case-insensitive,
bare number means bytes). Examples: `"> 1MiB"`, `"<= 4096"`.

**Regexes** are Python `re` syntax, compiled once at config load, applied as
bytes patterns (§8). An invalid pattern is a config error.

**Globs** are gitwildmatch (gitignore semantics) via `pathspec`. Note `*` does
not cross directory separators; `**` does.

### 3.5 Matcher references

`matches` is an ordinary facet. It ANDs with siblings and ORs across its own
list, exactly like `path`:

```toml
# generated files, but only under the API directory
exclude = [
  { matches = ["generated"], dir = ["src/api/**"] },
]
```

Matchers may reference other matchers. Reference cycles are a config load error
naming the cycle. Referencing an undefined matcher is a config load error.

### 3.6 Built-in global exclusions

Shipped with the script, active unless `extend_builtin = false`:

```
**/*.lock, **/package-lock.json, **/yarn.lock, **/pnpm-lock.yaml,
**/Cargo.lock, **/poetry.lock, **/go.sum, **/composer.lock,
**/vendor/**, **/node_modules/**, **/.venv/**, **/venv/**,
**/*.min.js, **/*.min.css, **/*.map,
**/__snapshots__/**, **/*.snap,
**/.git/**
```

Deliberately conservative. It covers files nobody reviews under any policy.
Generated code, tests, and docs are **not** here — those are review surfaces
whose treatment is a per-repo decision, and they belong at group level so they
still count toward `total`.

### 3.7 Validation

Config load must reject, with a message naming the offending key:

- Unknown top-level keys, unknown facet names, unknown rule-list keys.
- `version` absent or not `1`.
- A group without `limit`. Error text must point at `report = true` on a
  matcher as the alternative for a bucket that needs no budget.
- Group or matcher named `total`, `exempt`, `unmatched`, `global`, or `limits`
  (reserved).
- A name used for both a group and a matcher.
- `matches` referencing an undefined matcher, or a reference cycle.
- Invalid regex, invalid glob, malformed `size` comparison, `mode` not a valid
  git file mode, `grace` outside `[0, 1)`.
- A limit metric other than `added`, `deleted`, `changed`.
- A `[diff_census.limits]` key other than `total` or `unmatched`.

Warn (do not fail) when a group's rules can never match — e.g. an `exclude` rule
that is a superset of every `include` rule and matches on file-level facets
only. Best-effort; do not attempt this analysis for line-level facets.

## 4. Diff acquisition

### 4.1 Refs

Default comparison is **three-dot**: `git diff --merge-base BASE HEAD`. This
measures only what the branch introduced. Two-dot would inflate every count with
commits that landed on the base branch after the branch was cut, causing the
gate to fire for reasons unrelated to the change under review.

- `--base REF` (default: the repository's default branch, resolved via
  `git symbolic-ref refs/remotes/origin/HEAD`, falling back to `main` then
  `master`)
- `--head REF` (default: `HEAD`)
- `--two-dot` — use `BASE HEAD` directly
- `--staged` — index against `HEAD`
- `--working-tree` — working tree against `HEAD`

If the merge base cannot be resolved, exit 2.

### 4.2 Git invocation

Always pass `--no-ext-diff --no-textconv`. A repo with textconv drivers
configured in `.gitattributes` would otherwise spawn an external program per
file — unbounded cost the script does not control, and output it cannot parse.

Rename detection (`-M`) is on by default; `--no-renames` disables.

Two acquisition paths, chosen automatically (§8):

- **`--numstat` + `--raw`** — per-file add/del counts, modes, blob OIDs. Used
  whenever no active rule needs line text.
- **`-U0` patch** — zero context lines. Used only when some active rule uses
  `content`, `comment`, or `change`.

### 4.3 Line accounting

- A counted line is a `+` or `-` line in the patch body. `+++`/`---` file
  headers, `@@` hunk headers, `diff --git` lines, and index/mode metadata lines
  are not counted.
- `\ No newline at end of file` markers are ignored.
- A modified line appears as both a deletion and an addition. Both count. This
  matches `git diff --numstat`.
- **Binary files** contribute 0 adds and 0 dels — git reports no line counts for
  them. They are recorded in `diagnostics.binary_files` so they are not silently
  invisible.
- **Renames** classify under the *new* path. A pure rename with no content
  change is 0/0.
- **Submodules** (mode `160000`) contribute 0/0 and are counted in
  `diagnostics.submodule_changes`.
- **Symlinks** (mode `120000`) are ordinary one-line text changes.
- **Mode-only changes** are 0/0.
- An empty diff produces all-zero buckets and exits 0.

### 4.4 File metadata

- **`size` and `mode`** come from the post-image blob for adds and
  modifications, the pre-image for deletions. Sizes are fetched with a single
  long-lived `git cat-file --batch-check` process (§8), never one subprocess per
  file.
- **`mime`** is derived from the path via `mimetypes.guess_type`, with the
  script's own supplementary table for types Python's map lacks
  (`.go`, `.rs`, `.ts`, `.tsx`, `.toml`, and similar). Content sniffing is not
  performed — it costs a blob read per file for a facet that is nearly always
  used as a coarse filter. Files with no guessable type report
  `application/octet-stream`.

## 5. Comment detection

`comment` is a facet with four values, not a boolean.

### 5.1 Why a lexer

Regex comment detection (`^\s*#`) fails in both directions: it fires inside
heredocs, markdown fenced blocks, and shebangs, and on string literals like
`color = "#000000"`; it misses every block comment continuation line and every
language whose comment token is not `#`. A gate that silently undercounts is
worse than one that does not attempt the classification.

Use **pygments**. Pure Python, lexers for ~500 languages, filename-based lexer
selection, and correct string-literal handling. Token types under
`Token.Comment` are the classification.

### 5.2 Mechanism

Comment state is a property of the **file**, not the line — a `+` line inside an
open `/* */` cannot be identified from the hunk alone, and `-U0` gives no
context at all. Therefore:

1. Fetch the full blob (post-image for `+` lines, pre-image for `-` lines).
2. Lex it once with pygments.
3. Produce a mapping of line number to classification.
4. Look up counted lines by the line numbers the hunk headers provide.

This runs only when some active rule uses the `comment` facet, and results are
cached by blob OID (§8).

### 5.3 Values

| Value | Meaning |
|---|---|
| `only` | Every non-whitespace token on the line is a comment token |
| `trailing` | Code and a comment on the same line |
| `none` | No comment tokens |
| `unknown` | No lexer for this file, or pygments unavailable, or file skipped by size cap |

`unknown` is a distinct value rather than being folded into `none` because the
two error directions are asymmetric. Treating an unrecognised language as
`none` means it counts fully — the safe direction for a budget. Treating it as
`only` would let an unfamiliar file extension silently zero out a large change.
Default behaviour therefore counts `unknown` as code, and
`diagnostics.unknown_lexer_files` records the count so a missing language
profile is noticed deliberately rather than through a PR that sailed past the
gate.

If pygments is not installed, every file classifies `unknown`, the run
continues, and a warning is emitted to stderr naming the missing dependency.
The script does not fail for want of an optional dependency.

### 5.4 Docstrings

`docstrings_as_comments` (default `true`) controls whether Python docstrings
count as comments. Pygments tags them `Token.Literal.String.Doc`, distinct from
`Token.Comment`, so this is a clean switch rather than a heuristic. Applies to
any language where the lexer emits `String.Doc`.

## 6. Classification pipeline

Per counted line, in order:

1. Evaluate global exclusion rules. On match: increment `exempt`, record the
   matched rule index for the `by_rule` breakdown, **stop**.
2. Increment `total`.
3. Evaluate every reported matcher. Increment each that matches. Matchers are
   always evaluated in full; the overlap policy does not apply to them, since
   they are observational rather than budgeted.
4. Evaluate every group. Increment each whose membership predicate holds,
   subject to the overlap policy.
5. If the line was claimed by no group and no reported matcher, increment
   `unmatched`.

### 6.1 Overlap policy

`overlap` in the config:

- **`"multi"`** (default) — a line counts in every group it matches. Group
  counts may sum to more than `total`.
- **`"first_match_wins"`** — a line counts in at most one group, the first
  matching group in **declaration order** in the config file. Implementations
  must preserve TOML table order.

## 7. Output

### 7.1 Schema

`--format json` (default):

```json
{
  "schema_version": 1,
  "refs": { "base": "main", "head": "HEAD", "merge_base": "a1b2c3d", "mode": "three-dot" },
  "groups": {
    "production": {
      "adds": 1200, "dels": 34, "changed": 1234, "files": 18,
      "limit": { "metric": "changed", "value": 400, "grace": 0.10, "hard": 440 },
      "status": "over"
    }
  },
  "matchers": {
    "generated": { "adds": 41, "dels": 0, "changed": 41, "files": 3 },
    "tests":     { "adds": 210, "dels": 12, "changed": 222, "files": 7 },
    "docs":      { "adds": 30, "dels": 2, "changed": 32, "files": 2 },
    "comments":  { "adds": 88, "dels": 5, "changed": 93, "files": 11 }
  },
  "totals": {
    "total":     { "adds": 1291, "dels": 34, "changed": 1325, "files": 22,
                   "limit": { "metric": "changed", "value": 1200, "grace": 0.10, "hard": 1320 },
                   "status": "over" },
    "unmatched": { "adds": 50, "dels": 0, "changed": 50, "files": 1 },
    "exempt": {
      "adds": 881, "dels": 113, "changed": 994, "files": 9,
      "by_rule": {
        "global[0]": { "adds": 620, "dels": 4, "changed": 624 },
        "global[1]": { "adds": 261, "dels": 109, "changed": 370 }
      }
    }
  },
  "diagnostics": {
    "binary_files": 2,
    "submodule_changes": 0,
    "unknown_lexer_files": 1,
    "oversize_skipped_files": 0,
    "files_read": 14,
    "blobs_lexed": 9,
    "cache_hits": 31,
    "elapsed_ms": 412,
    "warnings": []
  }
}
```

`files` is the count of files contributing at least one line to that bucket.
`status` is `"ok"`, `"warn"`, or `"over"`, and is present only where a limit is
configured.

Grand total is `totals.total.changed + totals.exempt.changed`, deliberately not
emitted as its own field to keep one obvious way to read every number.

### 7.2 Text format

`--format text` prints an aligned table of groups, then matchers, then totals,
with limits and status shown where configured, and a diagnostics footer. Intended
for humans reading gate failures in CI logs. Exact layout is at the
implementer's discretion; it must not be parsed by anything.

### 7.3 Gate mode and exit codes

Gate mode is the default when the config defines at least one group. `--census`
forces report-only. `--gate` forces gate mode.

| Code | Meaning |
|---|---|
| `0` | All limits satisfied, or within a grace band (warn), or census mode |
| `1` | At least one limit exceeded past its grace band |
| `2` | Could not measure |

Exit 2 covers: config not found where explicitly requested, config invalid, git
invocation failure, merge base unresolvable, not inside a git repository, and
**gate mode requested with no groups defined**. That last case is the important
one — a misconfigured gate must not silently pass everything. Note this is
checked at gate time, not at config load: a config with matchers and no groups
is valid for census use, which is what the tool is named for.

**Grace band:** for limit value `L` and grace `g`, the hard threshold is
`L * (1 + g)`. Below `L` is `ok`. Between `L` and `L * (1 + g)` inclusive is
`warn` — reported prominently, exit 0. Above is `over`, exit 1. The grace band
warns; it does not move the limit.

A limit table may specify any of `added`, `deleted`, `changed`. All specified
metrics must pass. `grace` defaults to `0.0`.

`[diff_census.limits]` budgets two census-wide buckets: `total`, the
denominator every group is a subset of, and `unmatched`, the part of it no
group and no reported matcher claimed. Groups carry their own limits, and
`exempt` is by definition not review surface, so neither is budgeted there;
any other name is a config error.

A limit on `unmatched` turns config coverage into a gate. `unmatched` grows
when the config has stopped describing the repository, and without a budget
that is visible only to someone reading the report.

### 7.4 `--explain`

`--explain [PATH]` prints, for every file (or only the given path), the
classification trace:

```
src/api/handlers.py  (+120 -8)
  facets: ext=py mime=text/x-python mode=100644 size=8.2KiB
  global:     no match
  matchers:   comments (12 lines)
  groups:     production  <- include[0] path="src/**"
                             exclude: no match
  counted:    production +112 -8 | comments +12 -0 | total +120 -8

vendor/lib/thing.go  (+620 -4)
  global:     EXEMPT <- global.exclude[1] path="**/vendor/**"
```

For rules using line-level facets, report the number of lines matched rather
than a single verdict. A rules engine without this is undebuggable, and it is
the first thing anyone reaches for when a number looks wrong.

### 7.5 CLI summary

```
diff_census.py [--base REF] [--head REF] [--two-dot | --staged | --working-tree]
               [--config PATH] [--format json|text] [--explain [PATH]]
               [--gate | --census] [--jobs N] [--no-cache] [--no-renames]
               [--quiet]
```

## 8. Performance

The tool runs on every PR in a stacked workflow, often repeatedly while
iterating. It must be fast on a cold run and near-instant on a warm one.

**Skip the patch entirely when possible.** Compile the active rule set at config
load and determine whether any rule uses `content`, `comment`, or `change`. If
none does, `--numstat` plus `--raw` supplies everything needed: a 50k-line diff
collapses to a few hundred rows and one git invocation, with no line iteration
at all. `change` alone is still satisfiable from numstat; only `content` and
`comment` force the patch path.

**Use `-U0` when the patch is needed.** Zero context lines, typically ~6x fewer
bytes to parse on a normal diff. Combined with `--no-ext-diff --no-textconv`
(§4.2).

**Three-valued file pre-pass.** Split every rule at compile time into its
file-level conjuncts (`path`, `dir`, `name`, `ext`, `mime`, `size`, `mode`,
resolved `matches`) and its line-level conjuncts (`content`, `comment`,
`change`). For each (file, group) pair, resolve to `IN`, `OUT`, or `DEPENDS`.
`IN` and `OUT` take numstat counts in bulk; only `DEPENDS` walks lines. On a
typical PR most files resolve without being read.

**Cache by blob OID.** Blobs are immutable and content-addressed, so a lexed
comment classification for a given OID is valid forever. Cache under
`.git/diff_census/`. Cache key must include the blob OID, the pygments version,
and the `docstrings_as_comments` setting, so a dependency upgrade or config
change invalidates cleanly. This is the largest win for the real workflow:
re-running the gate on an iterating branch relexes only touched blobs, and CI
reruns on an unchanged head are nearly free. `--no-cache` bypasses.

**Batch git object access.** One long-lived `git cat-file --batch-check` for
sizes and one `git cat-file --batch` for blob content, fed OIDs on stdin.
Process spawn dominates all other costs past a few hundred files.

**Compile once, at config load.** `re.compile` every content pattern; build one
`pathspec.PathSpec` per glob list rather than N `fnmatch` calls; union
alternatives within a facet into a single alternated regex rather than looping.
Sort conjuncts within a rule by cost class so `ext`, `mode`, and `size`
short-circuit before `content` and `comment` are ever evaluated.

**Work in bytes.** Compile content patterns as bytes patterns and scan the patch
stream without decoding. Avoids a UTF-8 decode pass over the entire diff and
sidesteps decode errors on files that are almost-but-not-quite text. Stream the
patch from stdout rather than reading it into memory, so memory stays flat
regardless of diff size.

**Bound the lexer.** Pygments is the only genuinely expensive component. Cache
lexer instances by extension — `get_lexer_for_filename` performs filesystem
guessing on every call. Skip files above a configurable size cap (default 1
MiB), classifying them `unknown` and recording them in
`diagnostics.oversize_skipped_files`. Per-file lexing is CPU-bound and
embarrassingly parallel, so `--jobs N` with a process pool is available as an
escape hatch; **default to 1**, since worker spawn costs more than it saves on
ordinary PRs.

**Report timings.** `diagnostics` carries `elapsed_ms`, `files_read`,
`blobs_lexed`, and `cache_hits`. When someone reports slowness, the stage should
be identifiable without guessing.

## 10. Test surface

Minimum coverage for the implementation to be considered done:

- Facet matching per facet type, including `ext = ""`, `mime` wildcards, each
  `size` operator and unit, and each git file mode.
- AND-within-rule, OR-within-facet, OR-across-rules.
- `include` omitted defaults to match-all.
- `exclude` beats `include`.
- Matcher references, nested references, cycle detection, undefined reference.
- Global exclusion is terminal — an excluded line appears in no group or matcher.
- `exempt.by_rule` attribution.
- `unmatched` accounting under both overlap policies.
- `first_match_wins` respects declaration order.
- Every validation error in §3.7.
- Grace band boundaries: exactly `L`, exactly `L * (1 + g)`, one over.
- Gate with no groups exits 2.
- Binary, rename, mode-only, submodule, symlink, empty diff.
- Block comments spanning hunk boundaries; `#` inside a string; shebang;
  markdown fenced code; docstrings both ways.
- pygments absent — run completes, all `unknown`, warning emitted.
- Numstat fast path and patch path produce identical counts for a config that
  works under both.
- Cache hit produces identical output to `--no-cache`.
